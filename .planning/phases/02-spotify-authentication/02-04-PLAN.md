<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Create Spotify Developer App</name>
  <action>
User must create and configure Spotify Developer App:

1. Go to https://developer.spotify.com/dashboard
2. Log in with your Spotify account
3. Click "Create app"
4. Fill in:
   - App name: "Conflicted Lineup" (or your preference)
   - App description: "Festival lineup to Spotify playlist"
   - Redirect URIs:
     - http://localhost:5173/callback (for local dev)
     - https://conflictedlineup.com/callback (for production - adjust domain as needed)
   - APIs used: Check "Web API"
5. Accept Terms of Service and click Create
6. Go to Settings and copy the Client ID
7. Create frontend/.env.local with:
   ```
   VITE_SPOTIFY_CLIENT_ID=your_actual_client_id
   ```

Note: You do NOT need the Client Secret for PKCE flow - only the Client ID.
  </action>
  <resume-signal>
Confirm by typing: "Spotify app created, Client ID configured in .env.local"
  </resume-signal>
</task>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 3: Verify complete authentication flow</name>
  <what-built>Complete Spotify OAuth authentication with PKCE flow, including login, session persistence, profile display, and logout</what-built>
  <how-to-verify>
1. Start the development server:
   ```bash
   cd frontend && npm run dev
   ```

2. Open http://localhost:5173 in browser

3. **Test Login Flow:**
   - Verify you see the LoginPage with:
     - App title and explanation
     - Visual example of poster -> playlist
     - Green "Log in with Spotify" button
   - Click the login button
   - You should be redirected to Spotify's authorization page
   - Authorize the app
   - You should be redirected back and see the UploadPage with Header

4. **Test Profile Display:**
   - Verify Header shows your Spotify display name
   - Verify your profile picture appears (or generic avatar)
   - Click on your profile to verify dropdown appears

5. **Test Session Persistence:**
   - Refresh the browser (F5 or Cmd+R)
   - Verify you're still logged in (not redirected to LoginPage)
   - Verify profile still shows in Header

6. **Test Logout:**
   - Click profile dropdown
   - Click "Log out"
   - Verify you're returned to LoginPage
   - Verify Header is no longer visible

7. **Test Session Clear:**
   - After logout, refresh the page
   - Verify you remain on LoginPage (not auto-logged in)

Expected results:
- All steps complete successfully
- No console errors related to OAuth
- Smooth transitions between states
  </how-to-verify>
